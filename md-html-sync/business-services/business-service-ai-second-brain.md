## Markdown-First Knowledge Architecture and Metadata Hygiene

Why Markdown? Plain Markdown files are lightweight, vendor-neutral, easy for both humans and LLMs to read, and naturally compatible with Git pull requests and version history. When a policy changes, a team member edits one Markdown file, opens a quick pull request, and the Second Brain re-indexes only the changed file within seconds. There is no proprietary database lock-in and no mystery about who approved a change.

Every note in the vault includes a tiny YAML header specifying the document owner, review date, access scope, and canonical status (active, draft, or deprecated). During retrieval, deprecated documents are excluded automatically so employees never accidentally follow last year's pricing or security rules.
