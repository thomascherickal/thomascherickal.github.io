## Adaptive Always-On Thinking & Reasoning Budgets

Earlier reasoning models forced developers into a binary choice: either disable extended thinking and accept superficial pattern-matching on hard bugs, or enable a massive fixed thinking budget and pay heavy latency penalties on trivial formatting steps. Claude Fable replaces that rigid switch with adaptive thinking.

Under adaptive thinking, the model evaluates the structural ambiguity, constraint count, and verification requirements of each incoming turn before deciding how many internal reasoning tokens to expend. When asked to rename a validated symbol or format a structured JSON summary from clean inputs, Fable spends minimal internal deliberation and streams the response immediately. When confronted with an asynchronous race condition spanning three microservices or an ambiguous database migration, it expands its internal thinking trace to test hypotheses, trace edge cases, and falsify flawed patches before emitting final code.

In agentic loops, interleaved thinking is equally critical. Rather than thinking only once before the first tool call and then blindly reacting to tool outputs, Fable reasons between tool invocations. After reading a failing test output, it pauses inside a thinking block to diagnose whether the failure stems from the implementation under test, an outdated mock fixture, or an environmental dependency mismatch.

## Million-Token Context Coherence & Prompt Caching

A one-million-token context window without prompt caching is economically impractical for multi-turn iterative loops. Claude Fable delivers exceptional cross-referencing fidelity across the full million-token span by structuring inputs into three distinct zones:

- Zone 1: Immutable System & Policy Prefix: Coding standards, security invariants, tool schemas, and architectural constraints. Placed at the very top of the prompt with a persistent cache breakpoint, this block is cached at \$0.20 per MTok rather than \$8.00 per MTok.
- Zone 2: Repository Architecture & Interfaces: Dependency graphs, interface declarations, database schemas, and active design documents. Placing a second cache breakpoint at the end of this zone ensures that dozens of subsequent agent turns reuse the exact same pre-computed key-value state.
- Zone 3: Dynamic Turn Execution Tail: Holds only the active task, recent tool outputs, and current verification diffs. By keeping mutations strictly at the tail, cache hit rates routinely exceed 85% across long engineering sessions.

## Production Python Implementation: Adaptive Thinking & Caching

Below is a complete, runnable Python implementation demonstrating prompt caching, adaptive thinking limits, and a deterministic tool execution loop:

#### `fable_agent_loop.py`
```python
import anthropic
import subprocess

client = anthropic.Anthropic()

SYSTEM_PROMPT = """You are a Principal Software Architect.
Analyze the codebase, diagnose root causes, and run test suites.
Never declare a task complete until verification tests pass empirically."""

def execute_sandboxed_tool(tool_name, tool_input):
    if tool_name == "run_test_suite":
        res = subprocess.run(["pytest", "-q", tool_input["test_path"]], capture_output=True, text=True)
        return res.stdout if res.returncode == 0 else f"FAIL: {res.stderr or res.stdout}"
    return "Unknown tool invocation."

def run_fable_agent(repo_spec, task_description, max_turns=8):
    # Zone 1 and Zone 2 cached for maximum token savings
    system_blocks = [
        {"type": "text", "text": SYSTEM_PROMPT, "cache_control": {"type": "ephemeral"}},
        {"type": "text", "text": f"REPOSITORY SPEC:\n{repo_spec}", "cache_control": {"type": "ephemeral"}}
    ]

    messages = [{"role": "user", "content": task_description}]
    tools = [{
        "name": "run_test_suite",
        "description": "Execute pytest on a target test file",
        "input_schema": {
            "type": "object",
            "properties": {"test_path": {"type": "string"}},
            "required": ["test_path"]
        }
    }]

    for turn in range(max_turns):
        response = client.messages.create(
            model="claude-3-7-sonnet-20250219",  # production model string with thinking
            max_tokens=8192,
            thinking={"type": "enabled", "budget_tokens": 4096},
            system=system_blocks,
            tools=tools,
            messages=messages
        )
        messages.append({"role": "assistant", "content": response.content})

        # Check for tool invocations
        tool_calls = [b for b in response.content if b.type == "tool_use"]
        if not tool_calls:
            final_text = next((b.text for b in response.content if b.type == "text"), "")
            return final_text

        tool_results = []
        for call in tool_calls:
            out = execute_sandboxed_tool(call.name, call.input)
            tool_results.append({
                "type": "tool_result",
                "tool_use_id": call.id,
                "content": out[:8000]
            })
        messages.append({"role": "user", "content": tool_results})

    raise TimeoutError("Agent exceeded turn ceiling without passing verification.")
```

## Enterprise Security, Zero-Retention & Auditability

Deploying long-horizon coding and research agents in corporate environments requires strict data governance:

- Zero Data Retention: Ensure commercial API agreements explicitly specify zero data retention so customer prompts and proprietary algorithms are discarded immediately after inference.
- Air-Gapped Tool Execution: Isolate all tool execution (such as bash commands, compilers, and test runners) inside ephemeral, unprivileged Docker containers with zero network access to production clusters.
- Audit Trail Logging: Persist full JSON records of model thinking summaries, tool arguments, and test output traces to provide compliance teams with a tamper-evident audit history for every code modification.
